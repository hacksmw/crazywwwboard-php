  2. Bugs
    1. Sharing DB between different systems is not supported.
       The reason is difference of Byte order, to transmit to different
       system, user should

       convert DB -> ASCII , ASCII -> DB.

       For example, transmitting DB from Linux to Linux is possible, but
       Linux to Solaris is impossible.

       There is 'tranDB' package which transfers DB file between incompatible
       systems.

    2. Explore 3.x or older, 'javascript:history.go(-n)' and
       'javascript:history.back()' have same function, so if a user click listing
       icon after reading documents, the previous page is displayed.  Though the
       list link has the value of 'javascript:history.go(-2)', Explore 3.x cannot
       work properly.
      This is due to displaying listing page saved in cache, in order to reduce
      the feedback time.

    3. Explore 2.x or older cannot recognize 'onMouseOver' java script, so
       listing page is not displayed correctly.


E. Installation

  1. File names

    Type-1) Installation Package (Compile)

    FILENAME : CrazyWWWBoard-VersionNumber.tar.Z

    ex) Version 2.0
        - CrazyWWWBoard-2.0.tar.Z

    Type-2) Binary (CGI file and createDB file only)

    FILENAME : CrazyWWWBoard-VersionNumber-export-Platform.tar.Z

    ex) Version 2.0 binary file for 'Sparc SUN Solaris 2.4'
        - CrazyWWWBoard-2.0-export-sparc_sun_solaris_2.4.tar.Z

  2. Installation

    1. Uncompress

      Type-1) Installation Package (Compile)

      Move compressed file to directory in which you install.
       - move /SOURCE_DIRECTORY/FILENAME /TARGET_DIRECTORY/
         (Users who want to install under'/cgi-bin' directory, read 'HTTPd
          Configuration')

      Uncompress
       - uncompress FILENAME.tar.Z  (extension .Z is deleted automatically)
       - tar xvfp FILENAME.tar
         (Uncompressed and 'wwwboard-VersionNumber' directory is created)
         (suppose that 'wwwboard' directory is created)

      Type-2) Binary (Executable)

      Installation Package should be installed already.

      Move Binary to (wwwboard) directory.
       - move /SOURCE_DIRECTORY/FILENAME /TARGET_DIRECTORY/

      Uncompress.
       - uncompress FILENAME.tar.Z  (extension .Z is deleted automatically)
       - tar xvfp FILENAME.tar
         ('CrazyWWWBoard.cgi' & 'createDB' are created.)

      Note) User's server should meet the following condition to use Binary file.
       - Files whose extensions are 'cgi' should be recognized and executed as
         CGI file.
       - CWB directory shouldn't be assigned as ScriptAlias.

      Note) Refer to 'Installation Recommendation' in 'HTTPd Configuration'.

    2. Compile

      ** Binary installation user pass this section.

      Execute install-sh..

      (C Compiler, ar, ranlib should be installed and Compiler should be assigned
       as 'gcc'. Check your PATH can access the software which is referred.
       Modify 'wwwboard/src/Makefile', if Compiler is assigned as other than
       'gcc'.)

       - cd /wwwboard
       - ./install-sh

     If Compile is completed, following files are created under 'wwwboard'
     directory.

       - CrazyWWWBoard.cgi
       - createDB

    3. Creating DB

      If UID and GID of server is different from those of directory and
      execution files of CWB, open 'CrazyWWWBoard.conf' file and modify before
      creating DB.
      (Recompile is not necessary, because this is a real time referred file.)

      DB is saved in 'wwwboard/data' Directory.
      The name of DB is 'DB_NAME.gdbm'.
      ex) The name of 'test' db is 'test.gdbm'.

       - cd wwwboard
       - ./createDB DB_NAME
       - chmod 777 data/DB_NAME.gdbm

     All the documents created by users are saved in this file and the files
     uploaded by user's are saved in 'wwwboard/data/DN_NAME'
     (Directory is created automatically).

     Caution) CWB 2.x version users can use old DB by moving DB to
     'wwwboard/data'. Moving old DB to newly installed CGI directory is
     recommended, because new version  adjusted bugs which the old version
     contains.

    4. Test

      Firstly, create 'test' DB. Then inserting following line into the HTML
      document or location window of browser.

      http://SERVER DOMAIN/PATH/CrazyWWWBoard.cgi?db=test

      ex) <A HREF="http://nobreak.cgiserver.net/cgi-bin/wwwboard/CrazyWWWBoard.cgi?db=test">CrazyWWWBoard</A>

      Note) Adjust Server Configuration, when icon is not displayed or internal
            server error occurs. (Refer to HTTPd Configuration)

   5. Deleting DB

      - cd wwwboard
      - ./removeDB DB_NAME

      Deleting is completed showing following messages.
      ---------------------------------
      Database name : test
      Database filename : data/test.gdbm
      Database directory : data/test
      ---------------------------------

      .. Deleted data/test.gdbm
      .. Deleted data/test

    6. CGI Configuration

      Modifying 'wwwboard/CrazyWWWBoard.conf', referring to comments according
      to your environment.

      Recompile is not necessary, because this file is referred automatically,

  3. HTTPd Configuration

   Following errors can occur depending on the directory where CWB is installed
   and the server configuration.  If any error occurs, follow to 'Installation
   recommendation'.

  *. Installation recommendation
     Supposing that the root directory of web server is httpd, generally speaking,
     Document root is 'httpd/htdocs' and CGI root is 'httpd/cgi-bin. 

     1) Create new directory (cgi-pub) under httpd.
       - cd httpd
       - mkdir cgi-pub      ('httpd/cgi-pub' is created)

      Install CWB under the 'httpd/cgi-pub/wwwboard' 

     2) Add followings to server configuration.

     [NCSA HTTPd]   conf/srm.conf
       AddType application/x-httpd-cgi .cgi
       Alias /cgi-pub/ /FULL_PATH/cgi-pub/

     [NCSA HTTPd]   conf/access.conf ([Option] disable directory indexing)
       <Directory /cgi-pub/*>
         Options ExecCGI FollowSymLinks
       </Directory>

     3) Restart the server.

     4) User can run CWB in following directory.

       http://HOST_NAME/cgi-pub/wwwboard/CrazyWWWBoard.cgi

     Note) If you want to cgi file is running only in cgi-bin or cgi-pub,
           Refer to '1. Case of execution denied.  Solution 1.'       

    1. Case of execution denied.
      HTTP Daemon(Web Server) deny any CGI execution in the directory other
      than 'cgi-bin' for security.

       ** Solution 1 : Modifying Server Configuration 
      User can solve this problem by adding following lines.  These lines
      let the server recognize any file whose extension is 'cgi' as a CGI and
      allow its execution.  

       [NCSA HTTPd]   conf/srm.conf
         AddType application/x-httpd-cgi .cgi

       ISPs won't allow this, because any file whose extension is 'cgi' can
       be executed no matter where it is.
       In this case, refer to 'Solution 2'or deny CGI execution by following
       commands.

       [NCSA HTTPd]   conf/access.conf
         <Directory /admhome/*>   ## /admhome/ACCOUNT  Allow account users'
                                  ## running CGI.
           Options ExecCGI Indexes FollowSymLinks
         </Directory>

        <Directory /home/*>      ## /home/ACCOUNT  Don't allow account
                                 ## users' running CGI.
          Options Indexes FollowSymLinks
        </Directory>

      Note) Other Web Servers should be configured similarly.

      ** Solution 2: Modifying real-time configuration file
      If 'Solution 1' cannot solve the problem, you should install under
      '/cgi-bin' directory. After installing CWB under 'cgi-bin' moving all the
       files under 'wwwboard' to Document root(htdocs).

       ex) httpd/cgi-bin/wwwboard/* -> httpd/htdocs/wwwboard/*

      Modify directory configuration in the 'wwwboard/CrazyWWWBoard.conf'.

      Note) '/PATH' in the directory configuration is a relative path whose
            base is Document root, 'PATH' is a relative path whose base is the
            directory where the CrazyWWWBoard.cgi is located.

    2. When characters are not displayed properly.
      This problem occurs, because server recognize CGI files as general document,
      even though their extensions are 'cgi', if CWB installed under the directory
      other than '/cgi-bin'.

      ** Solution : Modify Server Configuration
      [NCSA HTTPd]   conf/srm.conf
        AddType application/x-httpd-cgi .cgi

    3. When ICONs are not displayed 
      This problem occurs if CWB is installed under '/cgi-bin'.
      Servers recognize all the files under '/cgi-bin' as CGI files, so try
      to execute ICONs and HTML files.

      ** Solution 1 : Modifying Server Configuration
      Solve the problem by assigning 'cgi-bin' as 'Alias' rather than 'ScriptAlias'.
      In this case using 'AddType', extension 'cgi' should be assigned as CGI.

      [NCSA HTTPd]   conf/srm.conf
        AddType application/x-httpd-cgi .cgi
        #ScriptAlias /cgi-bin/ /PATH/cgi-bin/     (Annotate using '#')
        Alias /cgi-bin/ /PATH/cgi-bin/     (Assign cgi-bin as Alias)

      In this case CGI files which have no extension under '/cgi-bin' cannot
      be executed, these files' name should be changed. If changing names is not
      possible, refer to 'Solution 2'.

      ** Solution 2 : Move ICONs to another directory
      Refer to '1. Case of execution denied.  Solution 2.' 

    4. DataBase Access Error : File open error
      This problem occurs when the permission of wwwboard/data/DB_NAME.gdbm
      is not correct or the DataBase doesn't exist. If the DataBase exist, change
      permission by following command.

      - cd wwwboard/data
      - chmod 777 DB_NAME.gdbm

    5. Your browser sent a non-HTTP compliant message 
       If above message appears in the writing page or password confirm page, try
       followings.

       1) Close users' browser.
       2) Delete cookie file in the directory where the browser is installed.
          (In the case of Netscape, 'cookies.txt')
       3) Retry.

     Above problem can occur when using a Netscape.

    uncompressed.

    wwwboard-VersionNumber --+-- message
                             |
                             +-- icon -- type
                             |
                             +-- data
                             |
                             +-- logs
                             |
                             +-- qDecoder-VersionNumber
                             |
                             +-- gdbm-VersionNumber
                             |
                             +-- src

      - head.html         (HTML header and tailer)
      - tail.html
      - mailhead.txt      (Mail header and tailer)
      - mailtail.txt
      - help.txt          (Help document)

    Directory 'icon'    -> ICONs used by CGI are saved here.

    Directory 'type'    -> ICONs used by uploading are saved here.

    Directory 'data'     -> DB(Data Base)s are saved here
      - DB_NAME.gdbm      (Name of user made DB)
      - DB_NAME           (Directory where uploaded files are saved)

    Directory 'logs'     -> Logs are saved here.
      - access.log        (Access log)
      - error.log         (Error log)
